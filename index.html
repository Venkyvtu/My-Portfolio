About

A developer who moved toward AI & agents

I started out as a software developer with a solid grounding in Python and Java, building backend logic and working through Computer Science fundamentals at Vel Tech University. Along the way I got pulled into machine learning — first as a way to solve specific problems like image classification, then as a broader interest of its own.

That interest has since moved toward Generative AI and Agentic AI: designing systems where multiple LLM-driven agents coordinate to complete a task end-to-end, rather than a single model answering a single prompt. I enjoy working across the stack this requires — orchestration logic, cloud infrastructure, data handling and the plain backend engineering that holds it all together.

I work well in collaborative environments, enjoy learning technologies as a project demands them, and I'm most motivated by problems where the solution isn't obvious at the start.

How I think about agentic systems

A conceptual view of the request path through an LLM-based agent — hover or focus a node for a short explanation. This reflects concepts I've studied and applied at prototype scale, not a specific production system.

User query The request or task, expressed in natural language.
LLM / Agent An LLM reasons over the query and decides what's needed next — answer directly, or call a tool.
Tools Functions, APIs or agent nodes (e.g. LangGraph steps) that the agent can invoke.
Knowledge / data Retrieved context — documents, database records or a vector store (RAG).
Response The final answer, ideally checked against guardrails before it reaches the user.

Streamlit UIUser-facing interface for uploading remittance files and reviewing results.

Remittance agentExtracts invoice numbers, ticket numbers, amounts and deductions from PDF/TXT remittance advice using LLM-based extraction with fallback parsing.
Cash application agentMatches extracted payments against invoice data with deterministic, pandas-based matching logic.
Dispute resolution agentHandles unmatched or contested items in the reconciliation flow.
Refund analysis agentAnalyzes cases that may require a refund.
Revenue leakage agentSurfaces patterns that point to revenue leakage across the pipeline.
